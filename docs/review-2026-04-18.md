## 阶段一：项目理解

### 核心业务闭环（诊断 → 训练 → 分析 → AI 辅助）

```
学生 登录 ──▶ DiagnosisSession (IN_PROGRESS 唯一)
              │  saveProgress / heartbeat / 自动提交
              ▼
         summarize ──▶ 生成 LearningProfile + 推荐 TrainingPlan
              │
              ▼
         TrainingSession (IN_PROGRESS 唯一) ──▶ Wrong-book / Review 计划
              │
              ▼
         analytics 聚合 ──▶ 教师画像 / 管理员看板
              │
              ▼
         RAG / AI Guidance (ai-gateway + pgvector)
```

**已核实**：
- 诊断/训练 session IN_PROGRESS 唯一性通过 **DB 生成列 + 唯一索引**（`V27__session_concurrency_and_idempotency.sql:56-75`）和 Service 层预检 + `DataIntegrityViolationException` 捕获双层防护（`DiagnosisSessionService.java:142-148`、`TrainingSessionService.java:179-183`），正确实现。
- Session 完成钩子（最近提交 `c7833d5`）通过 `TransactionSynchronization.afterCommit` + 独立任务执行器 + 新事务模板实现（`DiagnosisSessionCompletionService.java:61-108`），状态机（PENDING/IN_PROGRESS/FAILED）+ 重试调度器（`SessionLifecycleScheduler.java:48-49`）完备。

### 三端 Capability 权限模型

- 枚举定义：`shared-kernel/.../UserCapability.java:3`；序列化走 `name()`（无 `code()/label()`），前端 `Capability` 类型严格匹配（`contracts.ts:14`）。
- 路由守卫：`App.tsx:78-90`（`RequireAuth`）+ `App.tsx:92-108`（`RequireCapability`）→ `format.ts:425-427`（`userHasCapability`）— 全部 45+ 保护路由走 capability 检查。
- **注意点**：`App.tsx:64`、`pages/student/Settings.tsx:42,271` 仍用 `primaryRole === 'STUDENT'`（见 §1.4 发现）。
