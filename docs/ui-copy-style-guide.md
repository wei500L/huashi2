# UI 文案与语义样式规范

## 目标
- 让 `zh-CN` 与 `en-US` 都保持单语完整，不再出现同一界面中英文语义词混用。
- 统一页头、副标题、按钮、badge、状态词和提示语气，减少“页面像产品、组件像后台”的割裂感。

## 语言规则
- 中文界面使用中文语义词；英文界面使用英文语义词。
- 产品名、技术缩写和编号可保留原文，例如 `EF.Transfer`、`CSV`、`#123`。
- 禁止裸露后台式英文标签，例如 `filters`、`published`、`summary`、`latest snapshot`、`PAST WEEK`。

## 标题结构
- 页头标题：只写页面职责，例如“学情分析”“诊断模板”。
- 页头副标题：写当前页能完成什么，保持 1 句。
- Section eyebrow：只写模块类别，不写长句，不用占位英文。
- Chart/Card 标题：直接写用户能理解的对象或结果，不追加后台说明。

## 按钮命名
- 主按钮统一使用动作动词开头，例如“开始诊断”“新建草稿”“查看结果”“导出 CSV”。
- 次按钮保持明确动作，不使用“处理一下”“进去看看”这类模糊表达。
- 禁止同义按钮并存，例如同页内同时出现“继续”“继续作答”“进入测评中心”指向相同动作。

## Badge 与状态词
- Badge 只承载状态或对象属性，例如“草稿”“已发布”“进行中”“高风险”。
- 状态 badge 统一走语义组件，避免每页自己拼颜色和文本。
- 枚举状态必须经过本地化映射后再显示，禁止直接展示原始 code。

## 提示语气
- 加载态：说明“正在做什么”。
- 空态：说明“当前没有什么”，必要时补“这不影响什么”。
- 错误态：说明“出了什么问题 + 是否可重试 + 下一步建议”。
- 提示语尽量使用完整句，不用后台式碎片表达。

## 实现约束
- 共享词汇优先放在 `src/lib/i18n/slices/ui.ts` 或 `src/lib/format.ts`。
- 页头、小标题、badge、默认状态文案优先复用公共组件：
  - `PageHeader`
  - `SectionEyebrow`
  - `StatusBadge`
  - `FeedbackState`
  - `ChartCard`
- 新页面不得再直接写 `text-[10px] uppercase ...` 形式的英文 section 占位标签。
